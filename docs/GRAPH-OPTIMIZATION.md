# DocGraph 图谱可视化优化方案（v0.2 修订版）

> 一句话：把图谱从"通用力导向散点网"升级为"**清晰分簇、主次分明、可切换、可记忆**"的关系网。
> 关联：[PRD.md](../PRD.md)（FR-310 分组类型表 / FR-501 性能 / FR-502-504 布局交互 / FR-506-508 筛选搜索）
> 变更记录：v0.2 依据技术评审修订——范围收窄（G2 制度类拆出）、修正内部矛盾与选型硬伤（见 §7）。

## 1. 优化目标（Goals）

### G1 · 图谱通用可读性（对任意文档）

- **G1.1 布局清晰**：节点基本不重叠、连接紧密的实体聚成簇、高连接度（hub）实体醒目；
- **G1.2 语义可辨**：实体类型（颜色+形状）、关系类型（线型/颜色）一眼可区分，图例常驻且与样式一一对应；
- **G1.3 交互可控**：布局可切换、**用户拖过的节点不被自动布局重置**、图例/引导常驻；
- **G1.4 规模可扩展**：2000 节点布局流畅（默认概览 + 标签 LOD 预留，FR-501 的 5 万节点目标不在本次范围）。

> G2（制度类条文树/规范网络/引用网络）自 v0.2 起**拆出本文档**，作为 v0.5 独立专项，见 §8 附录。

## 2. 优化依据（Basis）

| # | 依据 | 说明 |
|---|---|---|
| 1 | **现状数据观察** | 当前 80+ 实体 / 60+ 关系的 `cose` 布局已出现节点重叠、孤立点散乱、hub 不突出——"乱"是真实可复现的问题 |
| 2 | **技术成熟度** | fcose / dagre / 社区检测（networkx greedy modularity）是关系图与有向图布局的标准成熟方案（cytoscape / Gephi 同思路）；circle/concentric 为 Cytoscape 核心自带，零新依赖 |
| 3 | **架构契合** | FR-310 分组独立类型表已支持按组注入类型表；`get_graph` 只需追加 `degree`/`community` 字段，**无需重构**抽取管线 |
| 4 | **PRD 对齐** | FR-501（性能）需布局/聚合支撑；FR-502 布局切换、FR-503 节点/边样式、FR-506/507 筛选搜索在本次范围；FR-504 拖拽固定与"拖过不重置"一致 |
| 5 | **依赖已就绪** | networkx>=3.2 已是项目依赖（pyproject.toml），社区检测零新增后端依赖 |

## 3. 预期效果（Expected Effects）

### 3.1 可量化指标（修正版）

| 指标 | 现状（基线需先录制） | 目标 |
|---|---|---|
| 节点重叠 | 常见（真实数据可复现） | **可测指标**：节点中心距 ≥ (半径和×0.9) 的节点占比 ≥ **95%**（"0 重叠"为硬承诺，不作验收） |
| 布局耗时 | 未测 | **2000 节点 ≤ 1s**（quality:"fast"/"draft" + animate:false + 主线程）；先录基线，超预算再评估 worker（见 §5.3） |
| 布局确定性 | 过滤/重渲染会重排、位置丢失 | **拖过不重置**；`randomize:false`；localStorage 记忆位置（key 含 project_id+group_id） |
| 边样式 | 全部同色同线型 | 按关系类型着色/线型，与图例一一对应（兑现 FR-503） |
| 上手时间 | 无图例/引导，靠摸索 | **1 分钟**看懂图例并完成"筛选 + 看证据" |
| 大图性能 | 80 节点可跑但乱 | 5000 节点可渲染；标签按缩放等级显示（LOD 预留） |

### 3.2 体验性效果（定性）

- 图谱：从"散点蜘蛛网" -> **几个清晰色簇 + 中心大节点 + 可辨识的关系线型**；
- 交互：从"拖一下全乱了" -> **我动过的永远不动，其余部分随意重排**；
- 新用户：图例/引导消除"不知道点哪、拖哪、代表什么"的困惑。

## 4. 度量与验收

- **前置**：先录制当前 cose 基线（重叠率、布局耗时、节点数/边数），作为对比基准；
- **每步落地后新增 Playwright 用例**：
  - 布局渲染成功、节点大小随度数变化、社区着色开关生效；
  - 布局切换（fcose/dagre/circle/concentric）生效且节点/边不丢失；
  - 拖节点后位置保留（重渲染/筛选后不动）、重置布局恢复自动布局；
  - 图例与样式一一对应（类型色、社区色、边线型）；
- **后端 pytest**：`get_graph` 返回 `degree`/`community` 字段；社区结果确定性（同图两次请求一致）；
- 提供**可用性自检清单**（拖拽 / 图例 / 筛选 / 切换布局 / 位置记忆），供人工快速验证。

## 5. 实施计划（v0.4 范围：第一步 + 第二步）

### 5.0 准备工作
1. 录制基线：当前图的重叠率、布局耗时、节点/边数（脚本化，进 selftest 数据）；
2. 更新 `src/docgraph/core/store.py::get_graph`：
   - node data 追加 `degree`（入+出度，客户端也可算，但由后端统一更稳）；
   - node data 追加 `community`（后端 `networkx.algorithms.community.greedy_modularity_communities`，**确定性、BSD 许可**；按 (project_id, group_id) 缓存，同图重复请求结果一致）；
   - 同步更新对应 pytest。

### 5.1 第一步：布局算法升级 + 可视化增强

| 项 | 方案 | 备注 |
|---|---|---|
| 布局 | `cose` -> `fcose`（cytoscape-fcose）；`quality` 按规模切换：≤300 节点 "default"，>300 "fast"；节点间距/边长调优、`randomize:false` | fcose 尊重 `locked` 节点，是"拖过不重置"的基础 |
| 节点大小 | 度数（入+出）映射 28~64px，hub 实体突出 | |
| 节点颜色 | **默认保持类型着色**（现 TYPE_COLORS）；「按社区着色」为画布工具栏**开关**，开启后填充色=社区色、描边色=类型色（双层表达，避免类型形状区分度崩塌） | |
| **边样式（补）** | 按关系类型着色 + 线型区分（实线/虚线/点线映射常见关系类型），兑现 FR-503 | v0.1 遗漏项，必须与节点样式同步上线 |
| 标签 | label 白色描边防重叠（`text-outline-width`/`text-outline-color`） | |
| 图例 | **常驻图例，与样式动态同步**：类型色、社区色开关、边线型说明；筛选后图例同步更新（FR-503 验收） | v0.1 遗漏项 |
| 保留 | 平移/缩放/控制按钮/隐藏孤立节点/移动节点模式 | |

### 5.2 第二步：布局切换 + 记住手动位置

| 项 | 方案 | 备注 |
|---|---|---|
| 布局切换器 | 力导向(fcose) / 层次(dagre) / 环形(circle) / 同心(concentric)；circle/concentric 核心自带，新增 `cytoscape-dagre` 一个依赖 | 兑现 FR-502 |
| 层次布局 | dagre，按有向关系展示演化/层级（制度类引用网络复用，见 §8） | |
| **位置记忆（关键实现细节）** | ① 渲染前**快照**所有节点位置；② `cy.elements().remove()` 后重加节点时先 `node.position()` 还原，再跑布局；③ **拖过节点自动 `locked`**，布局/筛选时不动；④ localStorage key = `docgraph_pos_{projectId}_{groupId}`（**必须带项目/分组标识，防串台**）；后端持久化本阶段不做 | 当前 render() 的 remove+add 会清位置，必须按此实现 |
| 重置布局 | 按钮清除所有 lock + 清除位置记忆，回到自动布局 | |

### 5.3 WebWorker 的决策流程（修正 v0.1 的硬伤）

- fcose **无官方 worker 模式**（布局默认主线程），v0.1 的"WebWorker 布局"写法不可直接落地；
- 做法：先用 5.0 基线 + 5.1 上线后的真实数据测 500/1000/2000 节点耗时；
  - 若主线程 ≤1s：**不引入 worker**（省掉 `cytoscape-in-worker` 依赖与坐标回传复杂度）；
  - 若超预算：再评估 headless cytoscape 于 worker 中算坐标、回传主线程的方案；
- 验收口径改为"2000 节点 ≤1s（主线程，fast quality）"，不再承诺 worker。

| 新增依赖 | 体积 | 许可 | 说明 |
|---|---|---|---|
| cytoscape-fcose | ~150KB(min) | MIT | 布局 |

## 7. 评审结论与修订记录（v0.1 -> v0.2）

本次修订依据代码现状与选型核实，结论如下：

| # | v0.1 问题 | 修订 |
|---|---|---|
| 1 | G2 制度类（条文树/规范网络/引用网络）超出"布局层"——需新解析器（条文结构）、新 prompts（跨条文引用）、新数据模型、新视图，与"不重构架构"原则矛盾 | **拆出本文档**，v0.5 独立立项（§8） |
| 2 | "规范类型表（应当/不得/…）"表意不清：模态词是**关系**语义而非实体类型 | 明确：制度组 entity_types=主体/行为/对象/条文，relation_types=应当/不得/可以/有权/依据/违反（见 §8） |
| 3 | "WebWorker 布局"硬伤：fcose 无官方 worker 模式 | 改为主线程 fast quality + 基线决策流程（§5.3） |
| 4 | G1.4"5000 节点"与 3.1"1000 节点"矛盾 | 统一为 2000 节点 ≤1s；5000 标注 LOD 预留 |
| 5 | G1.2 承诺边样式，第一步实施表却无此项 | 第一步补"边按关系类型着色/线型 + 图例同步"（§5.1） |
| 6 | "0 重叠"为不可达硬承诺 | 改为可测指标（中心距约束 ≥95% 节点） |
| 7 | 社区着色与类型着色冲突、图例失效 | 类型色默认 + 社区色开关，描边/填充双层表达；图例动态同步 |
| 8 | 社区检测未指定算法与许可 | 固定 `greedy_modularity_communities`（确定性、BSD）；禁止 python-louvain（GPL） |
| 9 | 位置记忆未写实现细节（当前 render() 会清位置） | 明确"快照→还原→locked→localStorage(pid+gid)"流程（§5.2） |
| 10 | 后端接口变更缺失 | `get_graph` 追加 `degree`/`community` + pytest（§5.0） |

## 8. 附录：G2 制度类展现（v0.5 独立专项，仅保留愿景）

> 本节仅作方向备忘，**不作为本次实施范围**。启动前需另立详细 PRD（参照 `docs/PRD-chat.md` 格式），核心待决策项：
> - **条文结构解析器**：pdfplumber/python-docx 目前只出文本块，需新增"编→章→节→条→款"层级识别（正则 + LLM 辅助）与条文编号归一；
> - **制度组类型表**（FR-310 配置）：entity_types=`主体/行为/对象/条文`，relation_types=`应当/不得/可以/有权/依据/违反`——模态词必须进关系表，勿混入实体表；
> - **三种视角**：条文树（默认视图）/ 规范网络（dagre 分层：主体→行为→对象，线型表达规范强度）/ 引用网络（"依据/被引用"关系）；
> - **数据流**：实体需绑定所在条文 → 详情面板与证据联动条文定位；
> - **依赖**：复用 §5 的 fcose/dagre 与社区检测能力，不新增布局栈。
