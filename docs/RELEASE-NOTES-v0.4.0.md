# DocGraph v0.4.0 发布说明

> 本次为 **三个用户问题的修复版**：提取语义错乱（法律文档）、文件分组逻辑难以理解、导出文件找不到位置。
> 同时修复了自测脚本在 Windows PowerShell 5.1 下的兼容性问题。

---

## 更新内容

### 1. 提取语义修复（法律/制度类文档）

**问题**：用默认"学术论文"类型表（提出/属于/基于/比较…）抽取法律文档，模型被迫硬套，
产出大量无信息量甚至荒谬的关系，例如：

- 女职工 ——属于——> 中华人民共和国劳动法
- 用人单位 ——比较——> 劳动者
- 中华人民共和国劳动法 ——提出——> 社会保险

**解决**：
- 新增 **法律法规抽取预设**：新建分组时可选择「学术论文 / 法律法规」，
  法律预设使用规范性类型表（实体：法律/法规文件、机构/组织、人员/角色、权利/义务、行为/事项、
  处罚/责任…；关系：规定、确立、保护、禁止、监督、实施、依据、授权、处罚、保障、适用、承担）；
- **Prompt 防垃圾规则**（所有分组生效）：
  1. 关系必须能读作「主语 + 关系类型 + 宾语」的通顺语句（如「劳动法 规定 女职工的特别保护」成立，而「女职工 属于 劳动法」不成立）；
  2. 类型表无匹配语义时**宁缺毋滥**，不得硬套；
  3. 禁止「某概念/主体 属于 某文件/某法律」这类泛化关系；「依据/基于」仅限原文明确表述。

> 注意：已抽取的旧数据仍是旧类型表的结果。验证方式：新建「法律法规」分组 → 把文档拖进去 →
> 重新点击「解析并抽取」（需真实 API Key）。

### 2. 文件分组逻辑重做（组织查看）

**问题**：导入文档会进入"当前选中的分组"，左栏是平铺列表，看不出文档属于哪个组，
也没有移动/复制能力——分组"难以理解"。

**解决**：
- 左栏改为 **「全部文件 + 分组树」**：顶部「全部文件」始终包含所有文档；
- **导入默认进入「全部文件（未分组）」**，不再受当前选中分组影响；
- **拖拽移动**：把文档直接拖到上方某个分组 = 移动；
- **复制**：文档行上的「⧉」按钮 = 复制到其他分组（自动重命名 报告 (2).pdf，副本为独立文档）；
- 「默认组」显示为「未分组」，每个分组显示文档数与抽取预设（学术/法律）。

### 3. 导出位置明确化

**问题**：导出走浏览器下载，文件静默进入系统下载目录，用户不知道去哪了。

**解决**：
- 所有导出（PNG / SVG / JSON / CSV）写入固定目录：%LOCALAPPDATA%\DocGraph\exports\<项目名>\；
- 导出成功后弹提示，**显示完整文件路径 + 「打开文件夹」按钮**（一键在资源管理器中定位）；
- 同名文件自动加序号（graph (2).png），不覆盖旧文件。

### 4. 自测脚本兼容性

- scripts/selftest.ps1 与 build_exe.ps1 转为 **UTF-8 带 BOM**（Windows PowerShell 5.1 按 GBK 误读中文导致解析失败）；
- $ErrorActionPreference 改为 Continue + $LASTEXITCODE 显式判定（native 命令 stderr 警告不再误中断）。

| # | 问题 | 根因 | 解决方案 |
|---|---|---|---|
| P1 | 女职工/未成年工"属于"劳动法 | 法律文档用学术关系类型表，LLM 被迫硬套 | 法律抽取预设 + prompt 防垃圾规则（宁缺毋滥） |

| P5 | selftest 偶发被 node 警告中断 | $ErrorActionPreference=Stop 下 native stderr 触发 NativeCommandError | 改 Continue + $LASTEXITCODE 判定 |
