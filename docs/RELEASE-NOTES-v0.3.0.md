## 二、问题与解决方案记录（重点）

### P1 前端黑屏/空白（v0.2.0 阶段遗留项，v0.3.0 保持）
- **现象**：窗口打开后页面空白。
- **根因**：Windows 上 Python `mimetypes` 把 `.js` 误判为 `text/plain`，浏览器拒绝执行 ES module 脚本。
- **解决**：静态挂载前注册正确 MIME（`.js->text/javascript` 等）。

### P2 已保存 API Key 仍提示缺失
- **根因**：后端抽取接口只认请求里传的 api_key，不读已存的凭据库 Key。
- **解决**：请求未携带时回退到已存 Key（`get_api_key()`）。

### P3 重启后文档"消失"
- **根因**：应用用浏览器 localStorage 记项目 id，WebView2 每次重启清空；且数据路径依赖启动目录。
- **解决**：数据/设置改存稳定目录 `%LOCALAPPDATA%\DocGraph`；后端持久化 `last_project_id`；启动时自动恢复最近项目；自动迁移旧数据。

### P4 删除文档报 405
- **根因**：**端口 8765 被残留的自测进程占用**，新 exe 的 API 未接管（访问的是旧服务），并非功能缺陷。
- **解决**：selftest 新增**端口/进程预检**（Step 0）；此类"新代码未生效"问题从源头规避。

### P5 最大化后「还原」无效
- **根因**：pywebview 的 `window.maximized` 属性在无边框窗口下不可靠，toggle 永远走 maximize。
- **解决**：改为**模块级自跟踪 `_maximized`**。

### P6 画布"无法平移"（节点拖拽冲突）
- **根因**：节点默认可拖拽，拖拽落在节点上=移动节点而非平移，误以为平移失效。
- **解决**：新增「平移/移动节点」模式切换，**默认移动节点**（直接拖实体），空白处平移。

### P7 拖动节点/画布时整个窗口被拖走（重点）
- **现象**：无论拖画布还是节点，都在移动窗口；最终窗口又无法拖动——反复"跷跷板"。
- **根因（源码核查）**：**pywebview 在 Windows（winforms+WebView2）根本没有实现任何鼠标拖窗口机制**：
  - `easy_drag` 只在 macOS/GTK/Qt/旧IE 实现，Windows 没有；
  - `-webkit-app-region: drag` 拖拽区在 Windows 不被处理；
  - 标准技巧 `SendMessage(WM_NCLBUTTONDOWN, HTCAPTION)` 也实测无效（WinForms WndProc 拦截）。
- **解决（终案）**：**绕开系统拖动，改为程序化定位**——前端在工具栏按下时轮询（约 60fps）光标坐标，Python 用 `GetCursorPos + SetWindowPos` 把窗口移到"光标-按下时偏移"，绝对坐标移动必然生效。
- **成果**：三项并存（拖工具栏移窗口 / 拖画布平移 / 拖节点移动），已实测通过。
- **详细记录**：见 `docs/TECHNICAL-NOTES.md`。

### P8 有大量孤立实体节点
- **根因**：抽取对每个概念建实体，关系仅在识别到语义连接时创建，因此部分实体无关系。
- **处理**：新增「隐藏孤立节点」开关；后续可用更优布局（fcose）与抽取策略优化。

## 三、下载与使用
1. 下载 `DocGraph.exe`（SmartScreen 点"更多信息 -> 仍要运行"）；
2. ⚙ 填 LLM API 配置（DeepSeek 等 OpenAI 兼容）-> 保存配置；
3. ＋导入文档 / 📂导入文件夹 -> 解析并抽取 -> 生成图谱；
4. 点实体/关系线看**来源与原文依据**；「调用日志」查模型请求/响应；导出 PNG/SVG/JSON/CSV。
