# DocGraph 图谱可视化与制度类展现优化方案

> 一句话：把图谱从"通用力导向散点网"升级为"**清晰分簇、主次分明、可切换、可记忆**"的关系网，并为**制度类（法律/规章/政策）文档**提供"条文树 + 规范网络 + 引用网络"的契合展现。
> 关联：[PRD.md](../PRD.md)（FR-310 分组类型表 / FR-501 性能 / FR-506-508 交互）

## 1. 优化目标（Goals）

### G1 · 图谱通用可读性（对任意文档）

- **G1.1 布局清晰**：节点不重叠、连接紧密的实体聚成簇、高连接度（hub）实体醒目；
- **G1.2 语义可辨**：实体类型（颜色/形状）、关系类型（线型/颜色）一眼可区分；
- **G1.3 交互可控**：布局可切换、**用户拖过的位置不被自动布局重置**、图例常驻；
- **G1.4 规模可扩展**：80 -> 5000 节点保持流畅（后台布局、默认概览、LOD 预留）。

### G2 · 制度类文档契合度（法律/规章/政策）

- **G2.1 结构契合**：按「编 -> 章 -> 节 -> 条 -> 款」呈现条文骨架（读者心智模型）；
- **G2.2 语义契合**：用**法律规范类型表**（应当/不得/可以/有权/依据/违反->承担）替代学术类型表；
- **G2.3 三种视角**：条文树 / 规范网络（主体 -> 行为 -> 对象）/ 条款引用网络（依据/被引用）；
- **G2.4 快速熟练**：图例 + 首次引导 + 上下文面板 + 确定性布局，新读者 1 分钟上手。

## 2. 优化依据（Basis）

| # | 依据 | 说明 |
|---|---|---|
| 1 | **现状数据观察** | 当前 80+ 实体 / 60+ 关系的 `cose` 布局已出现**节点重叠、孤立点散乱、hub 不突出**——"乱"是真实可复现的问题 |
| 2 | **法律/制度领域语义** | 法律读者心智模型是「目录 + 条文编号 + 权利义务」，不是抽象概念网；法律关系是**规范性**（应当/不得/可以/有权/依据），与论文关系（提出/基于/改进）**本质不同**——语义不对，图必乱 |
| 3 | **阅读高频动作** | "这条依据什么""谁应做什么""被哪些条引用" -> 对应**引用网络、主体-行为-对象、条文定位**，而非概念相似度 |
| 4 | **技术成熟度** | fcose / dagre / 社区检测（Louvain、模块度）是关系图与有向图布局的**标准成熟方案**（cytoscape / Gephi 同思路）；改动集中于前端布局层与抽取配置，风险低 |
| 5 | **架构契合** | **FR-310 分组独立类型表**已支持"制度组使用法律语义类型表"，**无需重构**即可落地制度语义 |
| 6 | **PRD 对齐** | FR-501（5 万节点 >= 30fps）需要布局/聚合支撑；"快速熟练"对应可用性指标（3 步出图、新手可用） |

## 3. 预期效果（Expected Effects）

### 3.1 可量化指标

| 指标 | 现状 | 目标 |
|---|---|---|
| 节点重叠 | 常见（真实数据可复现） | **0 重叠**（fcose 防碰撞/间距） |
| 布局确定性 | 过滤/重渲染会重排、位置丢失 | **拖过不重置**；布局稳定（randomize:false） |
| 上手时间 | 无图例/引导，靠摸索 | **1 分钟**看懂图例并完成"筛选 + 看证据" |
| 大图性能 | 80 节点可跑但乱 | 1000 节点布局 **< 1s**（WebWorker，不卡 UI） |
| 制度概览 | 直接铺 80+ 概念点 | 默认按「章」聚合 -> 概览约 **7 个章节点**，点开展开 |

### 3.2 体验性效果（定性）

- 图谱：从"散点蜘蛛网" -> **几个清晰色簇 + 中心大节点**；
- 制度文档：从"概念网" -> **条文树 + 权利义务网络 + 引用追踪**，符合法律读者直觉；
- 新用户：图例/引导消除"不知道点哪、拖哪、代表什么"的困惑。

## 4. 度量与验收

- 每步落地后**新增 Playwright 用例**：
  - 布局渲染成功、节点大小随度数变化、社区色分组；
  - 布局切换生效、拖节点后位置保留、重置布局恢复；
- 提供**可用性自检清单**（拖拽 / 图例 / 筛选 / 切换布局），供人工快速验证。

## 5. 实施计划（分步，先不动手）

### 第一步：布局算法升级 + 可视化增强（fcose + 度数 + 聚类）

| 项 | 方案 |
|---|---|
| 布局 | `cose` -> `fcose`（cytoscape 扩展）；参数 `quality:"default"`、节点间距/边长调优、`randomize:false`（确定性） |
| 节点大小 | 度数（入+出）映射 28~64px，hub 实体突出 |
| 聚类着色 | 后端 networkx 社区检测（greedy modularity / Louvain）计算 community id -> 前端按社区着色，类型用节点形状区分 |
| 标签 | label 白色描边防重叠 |
| 保留 | 平移/缩放/控制按钮/隐藏孤立节点/移动节点模式 |

### 第二步：布局切换 + 记住手动位置

| 项 | 方案 |
|---|---|
| 布局切换器 | 力导向(fcose) / 层次(dagre) / 环形(circle) / 同心(concentric) |
| 层次布局 | 新增 `cytoscape-dagre`，按有向关系展示演化/层级 |
| 位置记忆 | 拖过节点自动 locked；布局/过滤时 locked 节点不动；localStorage + 可选后端持久化 |
| 重置布局 | 按钮清除所有 lock 回到自动布局 |

### 第三步：制度类展现模式

| 项 | 方案 |
|---|---|
| 法律语义类型表 | 制度分组使用（应当/不得/可以/有权/依据/违反->承担）替代学术类型表（经 FR-310 分组配置） |
| 条文树视图 | 按 编->章->节->条->款 呈现 + 主体/行为/义务标签（默认视图） |
| 规范网络 | 分层布局：主体 -> 行为 -> 对象；线型/颜色表达规范强度（应当/不得/可以/引用） |
| 引用网络 | 「依据/被引用」引用关系，径向/引用图呈现 |
| 图例与引导 | 常驻图例 + 首次 3 步引导 + 按规范类型筛选 |
